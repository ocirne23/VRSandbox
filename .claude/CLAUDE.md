# Project Description
A modern c++ Game Engine codebase. Windows/MSVC only. The `App` executable is the testbed: it spawns `Entities/SponzaScene.pre` (Sponza + skysphere prefabs, Sponza with a static mesh collider) and `Entities/character.pre` (skinned, animated, scripted character) through the `World`, runs an ImGui editor UI (scene hierarchy, properties, asset browser, visual-script node editor, tweaks) around the viewport, and drives a transform gizmo. VR is initialized with `EVr::DISABLED` in main.cpp â€” flip to `ENABLED` to run on an OpenXR headset. A Bistro scene (`Entities/BistroScene.pre`) exists as an alternative test scene.

## Building

	* Reconfigure: `cmake -B Build` (only needed when files are added/removed â€” all sources are globbed, never edit CMakeLists to add files)

	* Output: `Build/x64/<Config>/App.exe`. Run from anywhere inside the repo; `FileSystem::initialize()` walks up to find `Assets/` and sets it as the working directory, so all asset paths are relative to `Assets/`

## Style
* Using exclusively c++20 modules instead of headers. (.ixx instead of .h)
	* Most libraries use module partitions: `export module RendererVK:Renderer;` in the interface .ixx, `module RendererVK;` in the implementation .cpp; public surface re-exported from `Public/<Lib>.ixx` (`RendererVK`, `Entity`, `Animation`, `File`, `Input` all do this)
	* `NetFuzz` is a second executable target next to `App` (Code/CMakeLists.txt globs subdirectories, so a new folder with its own CMakeLists is picked up on reconfigure)
	* `Core` and `UI` use dotted module names instead (`Core.Tweaks`, `UI.NodeEditor.Scene`, one module per .ixx)
	* `Public/` folder .ixx's are importable from outside the library; `Private/` is internal
	* The `Core` module re-exports std headers as header units â€” if you need a std header that isn't available, add it to `Code/Core/Public/Core.ixx`
	* `Core.fwd` / `*.fwd.ixx` modules hold forward declarations
	* One exception: `Script/Public/ScriptAPI.h` is a plain header â€” it's the ABI shared with runtime-compiled script DLLs and is `#include`d on both sides
* Modernest conventions
	* No new/delete, only memory safe types.
	* Raw pointers are non-owning
	* Minimal comments, only in exceptional cases where code intent is too difficult to communicate
	* Prioritize performance
* Engine singletons live in `export namespace Globals` inside the owning .ixx (`Globals::rendererVK`, `Globals::device`, `Globals::input`, `Globals::ui`, `Globals::world`, `Globals::physics`, `Globals::scriptHost`, `Globals::scriptEvents`, `Globals::assetRegistry`, `Globals::time`, `Globals::allocator`, ...). RendererVK globals use `#pragma init_seg` to control construction order â€” keep that when adding one. Globals in *different* libraries have no defined construction order relative to each other (see `ScriptEventManager::initialize` for the pattern when one global must register with another)
* int8/uint64-style typedefs from `Core`; glm via `Core.glm`; `assert` is compiled out in non-debug via forceinclude.h

## RendererVK
* Modern Vulkan renderer designed to only use modern features (minimum spec RTX 2000 series)
* Device Generated Commands (DGC) for everything
* Lights culled with a world space hash table indexing into grids with a cellcount based on distance to camera
* Global illumination using scrolling clipmap radiance cascades (ray traced probes)
* RTAO, TAA, PCSS cascades, volumetric fog, GPU compute skinning
* Long-range sun shadows ("Shadows/Terrain march *"): the PCSS cascades end at `Max distance` and the RT sun path's instances at `RT/TLAS Range`, both far inside a terrain mesh ring that runs to ~33 km, so past them the ground goes uniformly lit. Distant pixels instead cone-march the baked terrain height cascades (`terrainSunVisibility` in `terrain_height.inc.glsl`, shared with the volumetric fog which has marched them since it shipped) and take `min` of the two terms — the march fades in inside the cascade range where both see the same ridge, so the handover has no seam. Steps double from `Terrain march bias` (also the self-shadow bias: the map's texels are coarser than the geometry standing on them), and the soft horizon test makes the result deterministic — no jitter, no temporal integration, stable under camera motion
* Everything upstream of composite is linear HDR: `EyeAdaptationPipeline` (log-luminance histogram + smoothed auto-exposure, compute) feeds `CompositePipeline` (fullscreen HDRâ†’display pass into the swapchain before ImGui; tonemap operators: off/Reinhard/ACES/AgX)
* Frame order (see `recordCommandBuffers()` / `present()`): skinning compute â†’ indirect cull â†’ light grid â†’ particle sim compute â†’ shadow cull + draw â†’ static mesh/G-buffer â†’ GI probes â†’ RTAO â†’ volumetric fog â†’ TAA â†’ eye adaptation â†’ composite + ImGui. Inside the scene-color pass: static mesh forward â†’ decals â†’ GI-probe debug â†’ debug lines â†’ particles â†’ fog apply
* Layer structure under `Private/`:
	* `Objects/` â€” thin Vulkan object wrappers (Device, SwapChain, Buffer, Pipeline, AccelerationStructure, GBuffer, SceneColor, ShadowMap, ...)
	* `Pipeline/` â€” one class per render pass/feature (GBuffer, GIProbe, RTAO, TAA, VolumetricFog, EyeAdaptation, Composite, Skinning, light grid + indirect/shadow culling compute, shadows). Each registers its own Tweak vars
	* `Data/` â€” MeshDataManager, TextureManager, StagingManager, ShaderDatabase (Aftermath)
	* `Renderer.ixx/.cpp` â€” orchestrates everything; per-pass `record*()` methods called from `recordCommandBuffers()`
	* `OpenXRSession.ixx` â€” VR: OpenXR session/swapchain wrapper (`Globals::openXR`, implements `IVrSession`). Two-phase init around Vulkan device creation (runtime dictates instance/device extensions + physical device); stereo rendering targets a 2-layer multiview swapchain; in VR the editor viewport sub-rect is ignored (full-extent render). `beginFrame(camera, viewportRect)` applies that rect - `setViewportRect` is private, so the rect can only change at a frame boundary, and beginFrame builds the frame's projection from its aspect. `Renderer::initialize` takes `EVr::ENABLED/DISABLED`
* Scene objects: an `ObjectContainer` wraps one loaded `ISceneData` (meshes/materials/textures, optional `MaterialOverrides`); `container.spawnNodeForIdx()` returns a `RenderNode` instance handle (RAII, move-only), `spawnSkinnedNode()` the GPU-skinned variant (an `AnimatorComponent` feeds its bone palette via `allocateSkinningPalette`/`setSkinningPalette`). Destroying a `RenderNode` recycles its resources without GPU sync (all per-frame data is re-uploaded anyway): transform slots go on a free list, a skinned node's whole allocation bundle (`Renderer::SkinnedInstanceBundle`) is parked in place and reused by the next `spawnSkinnedNode` of the same container, and rebased sub-node instance offsets are uploaded once per NodeSpawnIdx and shared. Container-level resources still live for the app's lifetime (`~ObjectContainer` TODO). Lights are added per-frame via `renderer.addPointLight/addSpotLight/addAreaLight/addLightInfo/...`
* Per-frame instance flow: `renderNode(node, passMask)` is LOCK-FREE (callable from any job between beginFrame/present; atomic cursor claims, monotonic — on overflow the tail drops for ONE frame, `m_instanceOverflowStart` CAS-min records the first failed claim and present() clamps the counter to it, capacity regrows next beginFrame; NEVER roll a bump cursor back). `addLightInfo/addFogVolume` are atomic-cursor lock-free, `addDebugLine` + the transform dirty lists are `PerWorker`-staged and merged in present(); Renderer::initialize requires the JobSystem first. It writes the node's instances + a per-node pass mask (`PASS_MAIN/SHADOW/GI`, Layout.ixx = Spatial's pass bits) into mapped per-frame buffers; the main indirect cull, shadow cull, and GI TLAS-instance writer each early-out on their bit (TLAS also range-bounds by `RT/GI / TLAS Range`). Render node transforms upload SPARSELY: write only via `RenderNode::setTransform` (change-detected, per-frame-in-flight dirty lists drained in `present()`) - a mutable getTransform would bypass the tracking
* Texture mip streaming (`TextureStreamer`, "Streaming" tweaks): DDS textures load tail-only (mips <= 128px) and stream mips in/out of a fixed VRAM budget by camera priority (projected-size pass in `renderNode`). Residency changes recreate the image and rewrite that slot in all 5 bindless texture arrays (UPDATE_AFTER_BIND, applied per frame slot in `recordCommandBuffers` after the fence wait); disk reads run on a worker thread; old images retire after NUM_FRAMES_IN_FLIGHT. Non-DDS/procedural/embedded textures are pinned at full res
* Mesh data streaming (`MeshStreamer`, "Streaming" tweaks): cooked scenes register each source mesh + its generated LOD levels as a "mesh set" carrying the byte ranges its data occupies in the .vsc cache; the vertex/index mega-buffers are free-listed (`MeshDataManager`, BitRangeAllocator in element-aligned buckets). When resident bytes exceed "Mesh budget (MB)", the least-recently-referenced sets unseen for "Mesh cold frames" evict: their MeshInfos get indexCount 0 (DGC draws/shadow/TLAS writes become no-ops with no re-record; static BLASes persist - they are snapshots of identical geometry) and their ranges return to the free list after NUM_FRAMES_IN_FLIGHT. An evicted set referenced again re-streams from the .vsc on a worker thread (attributes re-interleaved to MeshVertex) and restores its MeshInfos at fresh offsets; the LOD selector renders the nearest resident level meanwhile. BLASes evict and rebuild with their set, and a LOD chain shares ONE BLAS at its "RT/BLAS LOD level" (alias table in AccelerationStructure; the TLAS-instance writer packs the aliased RT meshIdx into each instance's sbtOffset, which hit shaders use for geometry fetches while materials stay per-instance); static BLASes are copy-compacted a few frames after build ("RT/BLAS compaction", fence-timed size queries, ~30-50% back) Only cooked static meshes stream - skinned/procedural/direct-import data is pinned. NOTE: with Spatial culling Off everything is referenced every frame, so only despawned containers and Col_ proxies ever go cold
* Mesh LODs ("LOD" tweaks): meshes/nodes named `LodN_<name>` form authored chains grouped under `<name>` (a `Lod0_X` node path also resolves as `X`; level>0 never instanced, like `Col_`); static meshes without authored LODs get meshopt-generated index-only chains (shared vertices, "Generated reduction" of the indices per level; pre-baked by the scene cache when the source was cooked, generated at load otherwise). Selection runs per instance ON THE GPU (mesh_lod.inc.glsl in the main + shadow cull shaders; params via UBO lodParams, so tweaks are live): instances are pushed referencing LOD0 and the cull redirects the draw to the selected level's MeshInfo — the CPU sizes every chain member's instance bucket to the chain's full count so any split fits, hysteresis state lives in a per-instance GPU slot range (RenderNode::m_lodStateBase + per-frame node bias buffer; races/garbage benign — clamped into the frame's valid band), the shadow cull selects stateless at 4x/+2 coarser, GI needs no selection (all levels alias one chain BLAS), and per-level pick counts read back to Stats a few frames late. Selection is screen-space error: generated chains carry per-level meshopt simplify errors (mesh-local units, scaled by instance scale, projected to pixels) and use the coarsest level under the "Max error (px)" budget — object size needs no separate tuning; authored chains without error data fall back to the projected-diameter/"Full-res pixels" metric. renderNode keeps every level of a referenced chain warm in the mesh streamer (once-per-group frame stamp), and the cull falls back to the nearest resident level (indexCount 0 = evicted) while a re-stream lands. Skinned meshes get bind-pose-generated chains too (index-only over the per-instance deformed output regions, which preserve source vertex ordering; per-instance MeshLodGroups registered at spawnSkinnedNode, recycled with the bundle; the per-frame skinned BLAS builds at the chain's "RT/BLAS LOD level"). Skinned output MeshInfos are excluded from static BLAS builds/compaction (uninitialized until the skinning compute runs; their addresses are owned per frame slot by the skinned rebuild)
* Try to record CommandBuffers once (not per frame) whenever possible; call `setHaveToRecordCommandBuffers()` after changes that invalidate them
* Shaders are GLSL in `Assets/Shaders/`, compiled at runtime with glslang (so shader edits don't need a rebuild â€” F5 in the app calls `reloadShaders()`). `*.inc.glsl` files are includes; `shared.inc.glsl`/`ubo.inc.glsl` define structs that must stay in sync with `Private/Layout.ixx` (`RendererVKLayout`). Compiled SPIR-V + source dumps land in `Assets/Local/` for Aftermath GPU crash analysis

## Entity
* The ECS. Inline component layout: an `Entity` (pos/scale/rot, parent, displayName (`unique_ptr<char[]>`, null when unnamed — `getName()`/`setName()`), spawn template, refcount, `typeBits`, `flags`) and its components live in ONE allocation â€” `typeBits` is a bitmask over the 10 component types (fixed order: Scene, Render, Animator, Physics, Audio, Particle, Force, Light, Network, Script — Script stays last; `EComponentID` in `EntityP.ixx`), and `getComponent<T>(entity)` / `hasComponent<T>` compute the byte offset from it at compile-time-known sizes (`Component.ixx`). Each component type is its own module partition under `Private/Components/` (`Entity:RenderComponent`, ...: the struct + its `get*SpawnInfo`/`write*SpawnInfo` in an .ixx, the bodies in a same-named .cpp implementation unit); `Private/Component.ixx` re-exports them all and holds only the SHARED machinery (`inlineSizes`/offsets/`getComponent`/`hasComponent`, `composeTransform`, `componentTypeName`, the tree-allocation break/contiguity helpers). The per-component .ixx's must not import `:Component` (cycle) — the .cpp implementation units see the whole module, so anything cross-component (`getComponent<T>`, `composeTransform`, `MaxInlineComponentTypes`) is used there, not in the interface. Adding a component type means: new .ixx/.cpp pair under `Private/Components/` with a `getId()` struct, `export import` it from Component.ixx, entry in `EComponentID` + `inlineSizes` + `componentTypeName` + create/destroy switches in Entity.cpp + a parse branch in `World::buildTemplate` + a write branch in Prefab.cpp + a require-slot fill branch in `ScriptComponent::syncScriptData` + an offset entry in Entity.natvis, bump `MaxInlineComponentTypes`, and (if it should be authorable) a section in the UI Entity Editor
* `EntityPtr`: intrusive refcounted handle (atomic on `refCount`); `Entity::create(template, transform)` placement-news into `Globals::entityAllocator` (thread-safe/lock-free: atomic chunk bump + tag-counted per-size-class Treiber free lists, spinlock only on chunk add; blocks <= `MAX_BLOCK_SIZE` 64KB). Entities form a tree via `SceneComponent::children` + `Entity::parent`; `reparentEntity` moves ownership
* Tree spawns are ONE allocator block: `Entity::create` allocates the template's cached recursive size (`EntitySpawnTemplate::treeAllocSize`, lazy) and the spawn recursion carves per-entity slices from a bump cursor. Freeing: while intact (`EEntityFlag_RootAllocation`/`ContiguousAllocation`) members skip their own free and the root frees the whole block in one call, verified by a refcount pre-walk at root destroy (`contiguousTreeSolelyOwned`); breaks SPLIT the allocation instead of reverting it: reparenting/deleting a member out of its birth tree (`breakContiguousAllocation`) demotes only the path ancestors to per-entity freeing and promotes every off-path subtree (and the departing member) to its own RootAllocation over its contiguous DFS range (subtree sizes come from each child template's cached `treeAllocSize`); the pre-walk failure fallback splits the same way, so an external ref only degrades the path to it recursively. Moving within the same allocation or moving/grafting a whole allocation root never breaks anything
* `Entity::update()` -> `updateTree`: per entity runs ScriptComponent -> AnimatorComponent -> PhysicsComponent, composes the world transform, refreshes the RenderComponent's SpatialIndex entry and pushes its `RenderNode` to the renderer (gated on `SpatialIndex::isVisible` when Spatial/Culling Mode >= SafeCull), recurses into scene children
* Entity state lives in `flags` (`EEntityFlags`), not in components: `EEntityFlag_Enabled` (`isEnabled`/`setEnabled`; off prunes the whole subtree from updateTree and suspends its physics bodies — serialized as an entity-level `Enabled false` next to Position/Rotation/Scale, default true so only the disabled state is authored) and `EEntityFlag_Frozen` (`isFrozen`/`setFrozen`; script Update + animator + physics don't tick, script events don't fire — what the Entity Editor sets on an open document). Frozen is a SUBTREE state carried by every member: `setFrozen` writes the flag down the whole tree, `Entity::create` inherits it from the spawn parent and `reparentEntity` makes a moved subtree adopt its new parent's state (so a frozen tree reparented to a root/unfrozen parent thaws — nothing distinguishes "frozen itself" from "frozen by an ancestor" any more). Every check is therefore a plain self `isFrozen()`, including from entry points outside updateTree (global script events, physics contact events). Script OnSpawn runs even when frozen. `EEntityFlag_PhysicsSuspended` is the latch behind the disable path (was a `SceneComponent::physicsSuspended` bool; a spare flag bit costs nothing and is there whether or not the entity has a SceneComponent — a Scene-only group node is the common disable target): set when `updateSelf` walks `suspendPhysicsTree`, so the walk doesn't repeat every frame, and cleared up the whole new ancestor chain by `reparentEntity` — anything joining a disabled subtree afterwards missed that walk, and without the clear its body stays live and colliding invisibly. The per-component `enabled` bools (Script/Animator/Physics) are independent of both
* PARALLEL entity update (`World::update(renderer, dt)`, "Entity/Update" Parallel tweak, default on; off = the serial depth-first `Entity::update` per root): the tree is walked BREADTH-FIRST BY DEPTH, one level at a time, the whole level concurrently (`parallelFor`, JobCost auto-grained). `Entity::updateSelf` is the non-recursive per-entity body (the ONE hot visit: all components together, in order) and instead of recursing it emits its enabled children as `EntityUpdateNode{entity, world, frozen}` into a `PerWorker<EntityUpdateStaging>` slot; the level barrier merges those slots into the next level's array. The barrier IS the ordering guarantee - a parent always finished before its children start, so a child reads its parent solely through `parentWorld` and every other write lands in the entity's own components. Thread-safe inline: scripts (the DSL's cross-entity access is parent->child writes / child->parent reads only - world queries like "entities in radius" are the known open hole), animator tick + `setSkinningPalette` (disjoint palette regions), dynamic-body pose reads, `RenderNode::setTransform`/`renderNode`, `SpatialIndex::updateEntry`, audio follow (per-source atomics), particle/force emitter slots. The pass writes to box3d NOWHERE - it only reads dynamic poses, and the simulation is not stepping (the one write left in `PhysicsComponent::update` is `setEnabled` on the enable-toggle edge, which runs from a worker unstaged). There is no deferral/sink mechanism; an earlier `EntityUpdateSinks` staging layer was removed once the per-frame writes were. The gizmo entity still uses the serial `Entity::update` (which is now a thin recursive wrapper around `updateSelf`, so there is only one copy of the body)
* `World` (`Globals::world`): `spawn("prefabName", transform)`, `spawnAssetFile("Entities/x.pre", ...)`, `createEmptyEntity`. Builds and caches `EntitySpawnTemplate`s (archetype + per-component `SpawnInfo` recipes) from parsed assets; caches `ObjectContainer`s, collision sources/meshes, and retargeted animation clip sets so each source file is imported once. `reloadPrefabs`/`invalidatePrefab` for editing (retired templates stay alive for live entities). OWNS the root entity list (`addRootEntity`/`removeRootEntity`/`rootEntities` (const-only)/`clearRootEntities` - all mutation through the World API (InputControls takes a `World&`); main must call clearRootEntities before returning: World is a global, cross-library static teardown order is undefined) and applies all queued `EntityChange`s via `handleEntityChange(change, camera, viewportRect)` (main just pipes UI/script events in; UI notifications route back through `setOnPrefabOpened`/`setOnEntityRespawned` callbacks since the dependency points UI -> Entity)
* `AssetRegistry` (`Globals::assetRegistry`): scans `Assets/` at startup and registers everything by name â€” `ObjectContainer` + `StaticMesh`/`SkinnedMesh` spawnables (.oc), `Animation` clips (.anm), `Animator` graphs (.apl), `Prefab`s (.pre)
* Prefabs: `savePrefab(root, path)` serializes an entity tree back to .pre (per-component `writeRenderSpawnInfo`/`writePhysicsSpawnInfo`/... — the spawn recipe is what gets written; components have no serialize hook of their own); spawned prefabs are locked instances (`EEntityFlag_PrefabInstance`, unpackable in the Scene panel); `prefabWouldCycle` guards recursive saves
* Components: `SceneComponent` (children), `RenderComponent` (RenderNode + local transform, static or skinned), `AnimatorComponent` (AnimationPlayer + AnimStateMachine from a .apl, ticks and pushes the skinning palette; gameplay via `stateMachine.setFloat/Bool/Trigger`, clip events via `onEvent`), `ScriptComponent` (runs a .scr each frame with the entity as `self`), `PhysicsComponent` (see Physics), `AudioComponent` (named triggerable sounds: `Component Audio` with `Sound <alias>` entries; each alias holds one or more `Path` clips â€” settings are per-`Path` children (`Volume`/`Pitch`/`Loop`/`Relative`/`ReferenceDistance`/`MaxDistance`/`Rolloff`) â€” plus an optional `Select` mode `Single`/`Random`/`RandomNoRepeat`/`Cycle` (`EAudioSelect`) that picks a clip per trigger; `trigger(entity, alias, overrides)` plays one, playing spatial sounds follow the entity unless a position override pinned them, buffers World-cached per path; demo: physicsCube.pre), `ParticleComponent` (see Particle), `ForceComponent` (see Force), `LightComponent` (one or more lights on the entity, pushed to the renderer per frame; see below)
* `LightComponent` (component ID 7): a LIST of lights on one entity (`Component Light` in .pre with a `Light Point/Spot/Area/Tube` child per light: `Color`/`Intensity`/`Range` + entity-space `Offset`/`Direction`, then `ConeAngle`/`EdgeSoftness` (Spot), `Width`/`Height` (Area), `Radius`/`Length` (Tube), `Rotation` (Area only), `Enabled`; component-level `Debug true` + the "Lights/Debug geometry" tweak draw wireframes of every light's reach/shape. Demo Entities/Debug/lightRig.pre). Lights are PER-FRAME RECORDS, not renderer-owned slots: `update` just calls `renderer.addLightInfo` (lock-free, so it rides the parallel entity pass) for each enabled light after transforming it into world space, and spawn/destroy own nothing. Not frozen-gated (placement, not simulation — an editor document lights its own scene), and range/width/height/length are WORLD units that do NOT scale with the entity (same rule as Force). `Direction` ALWAYS means the direction the light POINTS, for every type - the renderer's encoding does not, and the component is what reconciles them (`LightFrame` in LightComponent.cpp): an area light's `LightInfo.direction` is the quad's HEIGHT axis (magnitude = height) with `rotation` the roll of the WIDTH axis about it, and the emission normal is `cross(up, right)` rebuilt from those (`areaLightBasis` in punctual_lights.inc.glsl) - passing the aim in directly puts the quad 90 degrees off, which is exactly what happened. So the component builds the frame instead: quad height axis = the entity's up projected into the quad plane (rolled by the authored `Rotation` about the NORMAL), width axis = `cross(axis, up)`, and `rollAroundAxis` re-encodes that as the renderer's `rotation`. A tube light never reads `rotation` (radially symmetric), so the editor hides it there. `TubeLight`'s constructor stores the FULL length — `doTubeLight` halves `|direction|` itself, so halving in both places rendered every tube at half its authored size. `lights` is a live copy of the SpawnInfo, so gameplay retunes a light in place. Script surface is OBJECT-shaped: a `Light` DSL STRUCT (mirrors `VrLight` in ScriptAPI.h -- enabled/color/intensity/range/offset/direction + coneAngle/edgeSoftness/width/height/length/rotation; each shape param is read by ONE type and harmlessly stored for the others, the TYPE itself stays authoring-only) and `self.light.lights`, a WRITABLE sequence scene.children-style: `foreach [ref] Light l in self.light.lights` / `ifexist [ref] Light l in ... at i` are the whole access surface (plus `self.light.count`). `lightGetAt`'s return value is the existence check, a `ref` binding's block-end write-back is `lightSetAt`, which clamps/normalizes host-side -- the struct members are freely writable on the COPY because the one write-back path validates. The struct also has intent-named shape setter FUNCTIONS (setSpotCone/setAreaSize/setTubeShape + tubeRadius reader) because the raw fields are overloaded per type -- a tube's radius rides the width field. `registerSequenceType` grew an optional `elementSetEmit` (-> elementWritable) for this. The ABI is ONLY `entityGetLightComponent`/`lightGetCount`/`lightGetAt`/`lightSetAt` -- no per-field thunks; the NodeEditor nodes (Get Light Component (handle + Count) / Get Light / Set Light, category "Light") go through the same pair, Get per-pin via `vrLightAt(...).field` and Set as copy-out / overwrite connected pins / `lightSetAt` copy-in. Entity Editor has a Light section (per-light collapsible blocks, add/remove). InputControls' test lights (keys 2-6 spawn one of each type at the camera, 7 bursts 100 points, 1 clears) are plain entities carrying this component - ALL sharing ONE lazily built template (same archetype; the values are written onto the live component, so they deliberately don't serialize), with `debugDraw` on instead of the sphere/cone/plane/capsule proxy meshes they used to place; main.cpp no longer pushes any lights itself
* MULTIPLAYER (transform + physics sync + events + headless server): `Entity:NetworkManager` (`Globals::networkManager`, imports Network) + `NetworkComponent` (ID 8, Script moved to 9, `MaxInlineComponentTypes` 10). The OWNER simulates freely and streams CLAIMS (ch3 Unreliable, claims are PHASE-LOCKED TO THE PHYSICS STEP — `send()` fires them only on a frame where `getStepCount()` changed, so every claim carries exactly one new step, which is the entire information the simulation produces. A free-running clock at the same nominal Hz beats against the step clock instead, duplicating one step pose and skipping another. "Max update Hz" (Network/Player) therefore survives only as a THINNING LIMIT (at most this often — half the step rate = every other step); above the step rate it never binds. Claims sample the RAW stepped pose, not the interpolated render pose (that one trails the sim by up to a step; smoothing belongs on the observer's playback buffer). Velocities are the body's own, a per-step quantity the server applies to its twin as-is. With physics PAUSED no steps occur so no claims go out, which is correct for a stopped sim): input (`NetInputState` — owner's controller writes `comp->input`, the server mirrors the accepted one for server-side gameplay) + claimed pos/rot/velocities, each packet carrying the last "Claim redundancy" claims (default 4; redundancy beats reliable under loss — a claim dies only after that many consecutive drops); the ring lives in the MANAGER (`m_claimRings`) so the inline component doesn't tax every networked entity. Claim payloads quantize like snapshots behind the same "Quantize" toggle (rot smallest-three u32, vels 3xu16 — the OWNER's live ±ranges ride in the packet header so a tweak mismatch can't decode garbage) and `look` is sent ONCE per packet, applied to every record server-side (~205 B/packet ≈ 4 KB/s per owned entity at defaults, was ~13). Claims follow the snapshot SLEEP policy (same `sleepDirty` field — the server uses it for snapshots, the owning client for claims, never both roles on one entity in one process): every tick while the body is awake, ONE rest-pose claim on the awake→asleep edge, then silence — an owned settled object costs nothing upstream. The server VALIDATES each claim ("Network/Validation" tweaks — note "Claim redundancy" lives under Network/Player and "Owner predict" under Network, since neither validates anything): a movement TOKEN BUCKET (metres, refilled at "Max speed" per second of SERVER WALL CLOCK, capped at half a second of it — never per-claim: seq numbers AND packet rate are both attacker-controlled, so any per-claim budget mints displacement per packet sent, an unbounded speed/wallhack), linear AND angular velocity caps (applied on EVERY accept path — the re-anchor and first-claim branches skip the displacement gate by design, and an accepted claim hands its velocity to the solver verbatim, so caps living inside the third branch made each of those a free impulse; ownership transfer resets the anchor, making the first-claim case repeatable), trajectory `castRayClosest` (wall teleports), hard teleport cap — the FIRST claim seeds the anchor but is still checked against the twin's current state (else an attacker's opening claim teleports free). Max speed must exceed the fastest LEGITIMATE motion including free fall (default 60). EVERY float off the wire is finite-checked and quaternions are re-normalized before reaching a body — NaN passes every comparison in a validator ("not greater than the cap") and would poison the solver for all players. Accepted → overwrite the twin (`lastAcceptedClaimPos` anchors the next budget — NOT the live twin, which contacts/corrections perturb) and flow to other clients as normal snapshots — via CLAIM PASSTHROUGH: the snapshot re-emits the newest accepted claim state (`claimStream*` fields) instead of sampling the twin, whose teleport-at-arrival + fixed-step pose age wobbles ±1 tick as the owner/network/server clock phases drift (remote clients replayed that as ~0.3s speed pulsing); a tick with no fresh claim extrapolates by the claim velocity, bounded at snapshotHz/maxUpdateHz+3 ticks before falling back to the twin (rate-aware: snapshots may legitimately outpace claims — e.g. 60 Hz snapshots over 20 Hz claims on a 20 Hz sim, which is the sanctioned low-latency configuration; the steady-state gap plus one lost claim packet must fit the budget), "Owner predict (ticks)" (Network category, default 0.5) adds a CONSTANT forward extrapolation at emit only, never accumulated — a fixed shift cannot jitter, unlike the arrival-phase-dependent extrapolation the twin used to do. higher values are prediction, trading overshoot on turns for less apparent latency, and Forced/Arbitrated/Asleep records always sample the twin (the authoritative state then); rejected → `violations`++ + `forcedUntilTick`, which stamps `NetRecFlag_Forced` on the entity's snapshot records — the owner ignores corrections UNLESS Forced (that one bit is the whole owner-side gating; non-owners ignore it). An ACCEPTED claim clears `forcedUntilTick` immediately (leaving it armed drags the owner toward its own RTT-old state — "stuck in mud" while moving), and `updatePlayerControl` YIELDS (input stops driving the body, intent still recorded) while the latest record carries Forced — steering against the correction breeds fresh rejections and turns the resync into a tug-of-war that only ends when the player releases the keys. Owner-side correction skip lives at the top of `NetworkComponent::update`. INTERACTION GRACE (Correction tweaks "Interaction radius"/"Interaction linger"): a server-owned body within the radius of one of OUR claim-driven bodies suspends its corrections (`localInteractionGrace` linger countdown) — they would drag it toward the server's RTT-old PRE-PUSH state and fight the shove the player is applying right now; the server twin receives the same push ~an RTT later through the claim-followed player body, so post-grace residue reconciles normally. TRANSPORT SECURITY: `NetHostConfig::encrypt` is ON by default (ECDH in the handshake + AES-128-GCM per payload packet, +16 B/packet, well under 1% of a core since the key handle is created once and AES is hardware). Not a tweak — the transport reads it at open() and it cannot change on a live host, so it is `NetworkManager::setEncryption()` before start, driven by `--no-encrypt`; both ends must match or the handshake denies. Without it a peer is identified only by SOURCE ADDRESS, so anyone who can forge one (trivial on a shared LAN) injects packets as another player — encryption, not TCP, is what fixes that (TCP offers no confidentiality or authentication; it only makes blind off-path spoofing harder). NetFuzz's `game` mode speaks the handshake by hand and needs the target run with `--no-encrypt`; its `host` mode smoke-tests the encrypted path with two real NetHosts. A client reads the field because the origin is a third party its connection knows nothing about. PHYSICS SYNC: a DYNAMIC-body entity syncs the BODY, not the entity — records set `NetRecFlag_Physics` and carry the body's WORLD pose + lin/ang velocities (3xu16 quantized over ±"Max vel"/"Max ang vel"; the ranges are live tweaks so they ride in the quantized message header — a differently-tuned client would otherwise decode garbage). Server: awake bodies send EVERY tick, then ONE record on the awake→asleep edge (`sleepDirty`), then keyframes only. Client corrections go through the thread-safe command queue (`teleportBody` + `queueBodyCommand` — NetworkComponent::update runs on job workers where even a velocity setter would wake the body into box3d's shared solver sets). DEFAULT correction is the PHYSICAL PUSH: between deadzone and snap the body is steered through the sim by `EBodyCommand::NudgeVelocity` — position/rotation error × `Push pos/rot gain` becomes corrective velocity ON TOP of the server's velocities (capped at `Push max (ang) vel`), delivered at drain as a center impulse of at most mass×`Push accel limit`×dt (angular twin as a capped velocity add — the ideal angular impulse I·dw lands on the same dw, so the inertia tensor cancels), so contacts/stacking/gameplay impulses COMPOSE with the correction and no teleport ever happens on this path (no prev/curr stomp needed; inside the deadzones nothing is queued, so bodies still sleep). Past `Pos/Rot snap threshold` the push enters CATCH-UP (gains + caps × "Push catch-up boost") so multi-meter errors still correct THROUGH the sim with legitimate contacts — teleporting into a space another desynced body still occupies would depenetration-fling both into fresh desync. The non-physical hard resync survives as the LAST resort at "Pos teleport threshold" (position only — a wrong orientation can't materialize inside anything): `teleportBody` + velocity sets, and EVERY teleport also stomps `PhysicsComponent::prevPos/currPos/prevRot/currRot` (the teleport applies next `physics.update` and prev/curr only refresh on STEP boundaries — without the stomp the render lerps from stale state; PhysicsComponent::update runs right after, same entity, and converts world→local itself). "Extrapolate" dead-reckons the pose target by linVel×timeSinceSnapshot (capped 0.25s). REMOTE-OWNED entities (other players) skip the chase entirely: BUFFERED SNAPSHOT INTERPOLATION ("Remote interp (ticks)", INT tweak, default and MINIMUM 2 — a buffer depth in whole snapshots, the cursor position being the fractional part; the cursor clamps to `newest - 1`, so a depth of 1 leaves no headroom and playback advances only on snapshot arrival, which the tweak's range now makes unauthorable. Buy smoothness with the snapshot RATE rather than the depth: 2 ticks = 33ms at 60Hz vs 100ms at 20Hz). The value MUST EXCEED 1 to actually interpolate: the cursor is clamped to `newest - 1` (no bracketing record below that), so at exactly 1 the drift target IS the clamp ceiling — the re-anchor pushes the cursor permanently into it and playback advances only when a snapshot ARRIVES instead of free-running per frame, degenerating remote motion to the snapshot rate . 2 gives a full tick of headroom and absorbs arrival jitter; it is cheap at a high snapshot rate (33ms at 60Hz vs 100ms at 20Hz), so raise the RATE rather than the tick count — `handleSnapshot` records their physics snapshots into a `NetSnapshotRing` (manager-owned `unique_ptr` map = stable addresses; component holds the raw pointer, main-write/worker-read) and `NetworkComponent::update` plays the trajectory back at `newestTick − interpTicks` (playback clock in SERVER tick units, `serverSnapshotHz()` from the Welcome; gentle drift re-anchor; slot-tick validation covers ring wrap + loss, a gap falls through to the physical push for that frame), teleport-following the interpolated pose with matched velocities + prev/curr stomps — a capped-accel body chasing a delayed input-spiky signal inherently lag-chases starts and overshoots stops, exact delayed playback reproduces them; the display delay is the trade. An asleep record hard-syncs once then queues `SetAwake 0`. Kinematic/static bodies use the entity-transform path (collider stays put, engine-wide rule); a record without the physics flag on a dynamic-body entity is ignored (server's twin suspended). ## Script
* Visual scripts compile to real DLLs: `ScriptHost` (`Globals::scriptHost`, depends only on Core) compiles a .scr with the installed MSVC toolchain (finds vcvars64.bat via vswhere, then `cl /LD /std:c++20 /MD /Od /Zi /DSCRIPT_BUILD`, force-including `ScriptAPI.h` via `/FI`) into a self-contained DLL under `Assets/Local/Scripts/`, caches by path, hot-reloads on demand (`getOrLoad(path, forceRecompile)`) â€” F6 or the Script panel's Compile & Run; live entities hot-swap. On failure the previous build is kept; superseded PDBs are garbage-collected around the debugger. A .scr is BODY-ONLY C++ (entry fns + optional ScriptData + helper fns + `//@graph` comments, no `#include`/`#define`); the wrapper supplies the ABI header. COOKED/SHIPPING alternative (CMake `option(SCRIPTS_STATIC)`, off by default, verified working): the `Code/AppScripts` target GENERATES one aggregate TU that `#include`s every `.scr` into its own `namespace Script_<stem>` (layout-mirror Entity, same as the DLL — no module import, so glm isn't dragged in twice) and compiles it straight INTO the engine, linking every engine lib like App. Each `.scr` ends with `REGISTER_*()` markers (`ScriptAPI.h`: empty in the DLL build, a `vrRegisterScriptEntry` static-init in the cooked build) so the aggregate needs no parsing — the file says which entries it has. `getOrLoad` then resolves from that registry instead of cl/LoadLibrary, so `ctx->*` calls are whole-program-optimized (/GL+/LTCG) and inlined against the engine thunks. All-or-nothing: one uncompilable `.scr` fails the whole aggregate (stale scripts must be fixed or removed)
* A .scr file IS the generated C++ (`#include "ScriptAPI.h"`, entry points `OnSpawn`/`Update`/`OnDestroy`/`OnEvent`/`OnPhysicsEvent` + `ScriptEventCount`/`ScriptEventName`/`ScriptDataSize`) with the node graph appended as `//@graph` / `//@node` metadata comments â€” the NodeEditor regenerates the code from the graph, and the file is also hand-editable C++
* `ScriptAPI.h` is the hostâ†”DLL ABI: C linkage, PODs/glm/raw pointers only (no STL, no engine types). The `ScriptContext` function table is APPEND-ONLY (cached DLLs compiled against older layouts must keep working). Scripts see a layout-compatible `Entity` MIRROR struct (pos/scale/rot/parent only â€” the layout past `displayName` is engine-internal); the engine static_asserts the offsets in ScriptContext.cpp so drift fails the build. Everything else goes through `ctx->entity*` functions (name, children, animation params, physics velocity/impulse/raycast, spawn/destroy, events). Components the script can't name are reached via an opaque handle: `ctx->entityGetForceComponent(entity)` returns the `ForceComponent*` as `void*` (null if none), and the `ctx->forceGet*/forceSet*(handle, ...)` calls cast it back host-side — one lookup, then cheap casts (the NodeEditor's Get Force Component node hoists the handle so the lookup runs once)
* `ScriptModule`: the loaded DLL's entry-point pointers + declared event names; don't cache the function pointers across reloads
* DSL engine surface: `math.*` is a NAMESPACE binding (`registerNamespace`, sidebar root, receiver-required so `sin(x)` is unauthorable) holding all scalar math -- basics/rounding/interpolation/trig/angles/random/quat constructors, ANGLES IN DEGREES throughout, with `vrInverseLerp/vrRemap/vrMoveTowards/vrDeltaAngle/vrWrapAngle/vrLerpAngle/vrMoveTowardsAngle/vrRandomUnitVector` in ScriptAPI.h for the formulas that would otherwise evaluate an argument twice. Randomness is one ENGINE-side generator (a DLL-local one would reset on hot-reload). `AnimatorComponent` is a full component type (`self.animator.setFloat/setBool/setTrigger/getFloat/getBool/setEnabled`, members `state`/`timeInState`/`speed`/`enabled`) -- animation is the animator's surface, never the entity's, and nothing names a clip (the .apl graph decides). A getter-call member MUST be `writable=false`: a writable member's emit is used verbatim as an assignment target
* ScriptData field VISIBILITY: each `//@@data` field carries `DSLFieldVisibility` Hidden (default) / Private / Public, spelled `//@@data private int num` (keyword omitted for Hidden, so older files round-trip byte-identically); arrays can never be exposed. A script exports its exposed fields as a `VrScriptField[]` table (name/type/offset/visibility, offsets via `offsetof`) through `ScriptDataFields()` — the ONLY thing that describes a ScriptData block's layout engine-side (`ScriptModule` holds it as `void*`, staying decoupled from the ABI header). The Properties panel edits those fields LIVE (never serialized, and refuses to draw while `scriptDataLayoutId` disagrees with the module); the Entity Editor authors INITIAL values, stored as text under `Component Script` / `Data` in the .pre and re-applied by `applyInitialValues` after every `syncScriptData` reallocation — without that, a `//@@data` edit would zero them on hot-reload
* DSL containers: `T[]` arrays live ENGINE-side (`VrArray` = a generation-tagged handle in ScriptData, storage in ScriptContext.cpp) so a hot-reload keeps them without copying. The ABI is type-erased (`arrayGet/Set/Push` + elemSize); the typed `vrArrGet/Set/Push` templates live in `ScriptAPI.h` (force-included, so generated code has no preamble). There is NO unchecked container read: `foreach [ref] <type> <n> in <c>` iterates and `ifexist [ref] <type> <n> in <c> [at <key>]` does the single bounds-/existence-checked lookup (`arrayGet`'s return value IS the check). Element bindings are COPIES; `ref` adds a write-back at block end (emitted only when the body assigns), so push/clear mid-loop drops a write instead of dangling an interior pointer. Non-`ref` elements are refused as assignment targets; `ref` is refused on handle types (Entity writes already propagate) and on containers registering `elementWritable=false`. `foreach` HOISTS the container resolve: a container may register `sequenceBeginEmit`, and when it does the loop resolves once into a local and `$r` in `sequenceCountEmit`/`sequenceAtEmit` is that local. POD arrays (everything but Entity/String) resolve to `ctx->arraySpan($r, sizeof(T))` -> `VrArraySpan{data,count}` and the at-emit is a plain `static_cast<const T*>($r.data)[$i]` — the whole loop is ONE ABI call and an element is a load. Entity/String arrays have no raw element to point at (refcounted `EntityPtr` / engine-owned `std::string`) and keep the checked per-element read via `arrayResolve`/`arrayViewCount`/`arrayViewGet` (the view is the `ScriptArray*` itself, safe to hold only because the registry's storage is chunked and never moves). THE SPAN IS VALID ONLY WHILE THE ARRAY DOES NOT GROW, and `mutatesContainer` is now the SAFETY rule that guarantees it (it used to be only a diagnostic): push/clear on a container an enclosing foreach/ifexist reads is refused. `ScriptLoader::checkContainerMutations` is the rule, and it runs over a whole DOCUMENT (per-function `{mutated (root,path) set, callees, unknown}`, fixed-point merge over the call graph, then every call made from inside a loop is re-checked) — so it catches the indirect case through any chain of user function calls. It is called from BOTH `save()` and `load()`: the editor's Save / Compile & Run path never parses (it goes straight to `Transpiler::transpile` + `save`), so a parse-time-only check does not run on the authoring flow at all — that mistake was made and fixed. A push through a PARAMETER sets `unknown`, poisoning that function for every caller — conservative on purpose, so no argument-to-parameter mapping is needed. The parse-time `checkContainerNotIterated` is kept only for the DIRECT case, where it reports at the offending line. NOTE the editor twin (`ScriptLang::isContainerIterated`, which filters push/clear out of the autocomplete candidates) is still SYNTACTIC — it won't grey out a user-function call that transitively pushes, so that mistake is authorable and gets refused at load instead of being unauthorable. A `ref` POD element binds STRAIGHT INTO the span as a C++ reference (`sequenceElementRefEmit`, `T& n = static_cast<T*>($r.data)[$i]`) — no copy in, no write-back out, so the copy and the storage cannot drift; `sequenceElementSetEmit` (`static_cast<T*>($r.data)[$1] = $v`) is the store-at-block-end fallback for containers that name an element but not an lvalue. A `ref` `ifexist` does the same through `lookupRefEmit` (`ctx->arrayElem`, cast to `T*`): the POINTER is the miss test, so there is no default-initialized copy and no store — it declares the pointer in the if's init-statement and binds the DSL name as a reference to it inside the body, leaving every expression that reads the binding unchanged. Entity/String arrays and every `ifexist` write-back still go through the checked `vrArrSet` on the handle. Sequences without a begin emit (scene children, spatial queries) emit exactly as before. Existing `.scr` files keep their old `vrArrGet` codegen until regenerated — `arrayGet` is unchanged, so nothing breaks. A container registers `lookupKeyType/lookupValueType/lookupEmit` (+ `elementSetEmit`) to gain all of this; `mutatesContainer` on a BindingFunc refuses push/clear inside a loop reading that same storage. Component members (`self.physics`) are self-ONLY (empty member path) — another entity's go through `ifcomponent`. `//@@require` is a CONTRACT enforced LIVE by `ScriptComponent::requirementsMet` (a `requiredComponents & ~typeBits` mask test) at every entry point — Update/OnEvent/OnPhysicsEvent/OnSpawn/OnDestroy plus `ScriptEventManager::fireEvent`, which calls `onEvent` directly off the module and would otherwise bypass all of them. Not latched at spawn: a hot-reload mutates the bound `ScriptModule` in place and never re-runs `spawn`, so a latched refusal outlives the edit that fixes it and needs an app restart. `OnSpawn` runs ONCE, the first frame the entity qualifies (late-constructed from `update` when it didn't at spawn, so a script fixed mid-session doesn't leave everything already spawned half-initialized), and sets `onSpawnRan`; `OnDestroy` is paired with THAT flag, never with the live check — teardown must be conditioned on construction having happened. Requirements going unmet while live still suppresses `OnDestroy` (a skipped teardown beats reaching for a refused component; the script's arrays free regardless). The ScriptData block is re-synced the same way: `syncScriptData` (re)allocates + refills the require slots + clears `onSpawnRan` whenever the module's `dataSize`/`dataLayoutId` no longer match the block's, and `syncScriptDataLive` (called from every post-spawn entry point) also re-registers the event listener, whose stored ScriptData pointer the reallocation would otherwise dangle. Without it a `//@@data`/`//@@require` edit left LIVE entities reading their old block under the new layout — spawn holds the only other copy of that check and never re-runs. The require-pointer slots at the front of ScriptData must have a fill branch for EVERY `EComponentID` in ascending order — a missing branch doesn't just leave its own slot unwritten, it shifts every later component into the wrong slot (Scene/Render/Animator/Particle were missing, so a script requiring Scene+Physics read the PhysicsComponent as its SceneComponent and crashed in `sceneGetChildAt`). There is NO null in the DSL: an absent value is an OPTIONAL type (`registerOptionalType`, spelled `Entity?`, e.g. `self.parent`) readable only via `ifexist Entity p in self.parent`, and a dead entity in an array reports a lookup MISS rather than binding null — so no manual null check exists or is possible
* The DSL scripting-language subsystem (data model, autocomplete rules, engine-exposure registry, native save/load, C++ transpiler) lives under `Private/DSL/` as partitions re-exported from `Public/ScriptHost.ixx` (`export import :DSL/:ScriptLang/:ScriptBindings/:ScriptLoader/:Transpiler`) — editor-agnostic, so it's here instead of UI even though UI's Script Editor panel is its only consumer today. Types an outside importer needs (`import Script;`) must be marked `export`, not just their free functions — a same-module partition lets unexported types leak across files, which is how these went unnoticed until the move. `ScriptEditor.ixx/.cpp` (the ImGui panel) stays in `UI` and reaches this via `import Script;`

## Force
* Forcefield bubbles: emitters (Team 0-7, Output, Reach, Focus, Distribution + direction) project ANALYTIC influence fields with compact support. The bubble spans EXACTLY the "output line" `pos .. pos + dir*Reach`: in normalized coords (X = axial [-1,1], Y = lateral/(Reach/2)) `u^2 = X^2 + (Y/width)^2*((1-X)/(1+X))^(1-2*focus)` (Width = pure lateral scale: 1 = round, < 1 pinches cones sharper / spheres prolate; reach untouched), `w = Output * (1-u^2)^2 * distGain(t)` — focus 0.5 = EXACT sphere spanning the line, 0/1 = exact cones pointed at the emitter/target (one "pinch" slider, reach never changes). `distGain` = smooth gaussian bump at t = Distribution along the line (0 = density at the emitter end, 1 = at the target). TOTAL output is invariant across focus/distribution/width (reference = the plain sphere): the fold `refBudget/(shapeBudget(focus,D) * width^2)` (1D quadrature cached per emitter in System.cpp) is pre-applied to the uploaded Output, so pinching/narrowing DENSIFIES the field instead of shedding power; reach still scales the total (bigger = more power, same density). Gradients are finite-differenced everywhere (no analytic gradient for the warped shape). Same-team fields SUM (metaball merging); a point is inside team t where `phi_t > iso` AND `phi_t` beats every other team, and the drawn surface is the equal-field equilibrium `F = phi_best - max(iso, phi_second) = 0` — squish/pierce fall out of the math, no simulation. Field math lives ONCE in `force_field.inc.glsl` (CPU lobe mirror in System.cpp drives the debug rings); links Core + RendererVK only
* `Globals::forceSystem` (`ForceSystem`): `initialize()` from main (registers ALL "Force" tweaks into a `ForceFieldParams` pushed via `renderer.setForceFieldParams` every update — setOceanParams pattern); `update(renderer, dt)` on the main thread after world.update = the only writer of renderer force state. `createEmitter(team, pos, dir, output, reach, focus)` -> RAII move-only `ForceEmitter` (`setTransform/setOutput/...` safe from the parallel entity pass — own slot only; `getOutput/getReach/getFocus/getDistribution/getWidth/getTeam` read live authored state immediately, `getAppliedForce()/getPressure()` = latched GPU readback ~2 frames old); `createQuery(pos)` -> `ForceQuery` ("is this point inside whose bubble" for territory control, same latency, `Result{owningTeam, inside, ownField, opposingField, valid}`)
* Renderer side (`RendererVK:ForceFieldPipeline`, slot API next to the particle block): emitter/query slots are main-thread with free-list + retirement (NUM_FRAMES_IN_FLIGHT+2 — readbacks are SLOT-indexed via `teamFlags.z`, so slots never re-pair with stale results); live slots compact-upload per present into a mapped buffer (count header + big-emitter index list). Rendering = one instanced indirect draw of unit cubes (decal pattern: front-cull, no fixed-function depth, premultiplied, after debug lines / before particles; per-eye sets for VR) whose FS ray-marches F through the emitter's oriented reach box (`forceEmitterBounds`, shared VS/FS/grid-insert), bisection-refines the hit, tetra-tap normal, manual reversed-Z depth test vs G-buffer; OWNERSHIP DISCARD dedups merged bubbles (only the fragment whose instance is the dominant contributor at the hit shades it). Shading: fresnel rim + team color + triplanar hex/noise pattern + contact glow (`phi_second/phi_best -> 1` at the seam) + geometry-intersection glow; all params UBO-live (`forceParams0..2` + team colors)
* Compute (`recordForceCompute`, after the light grid): rebuilds a UNIFORM 32 m emitter hash grid per frame (`force_grid.inc.glsl`, 3rd hash_grid.inc user; fixed 64-emitter cells, light-grid CAS-claim/bump-alloc/overflow-inflated-counter contract, `checkForceGridCapacity` grows from the header readback); emitters over "Big reach threshold" bypass into a globally-scanned <= 64 list (a 300 m dome would flood thousands of cells). `force_emitter.cs` integrates the opposing-field pressure per emitter (13-sample own-field-weighted integral — a center-only tap reads zero when big bubbles press rims without center overlap) and `force_query.cs` evaluates registered points; both write straight into host-visible readback buffers (ocean contract: CPU copies between beginFrame's fence and present, ~2 frames latent). "Force/Use grid" off = brute-force scan A/B toggle (FORCE_GRID define, pipeline rebuild like ocean hit lighting)
* Entity integration: `ForceComponent` (`Component Force` in .pre: `Team`/`Output`/`Reach`/`Focus`/`Distribution`/`Width`/`Centered` + local-space `Direction`/`Offset`; demo Entities/SphereField.pre) owns a `ForceEmitter` and keeps it on the entity's world transform each update (not frozen-gated — placing a bubble isn't simulation, and a gizmo-dragged editor document must carry its field). The emitter sits at the START of the span (`Offset .. Offset + Direction * Reach`); `Centered` (default true, Entity Editor checkbox) pulls the emitter back `Reach/2` along the axis so a zero `Offset` puts the bubble CENTRE on the entity (a non-zero offset then shifts it from there), off = the span starts at the entity. Reach is world units and does NOT scale with the entity. No authored on/off — Force has no such concept, so a script silences one with `emitter.setOutput(0)`. Component ID 6. Scripts drive it through the `ctx->entityGetForceComponent`/`forceGet*`/`forceSet*` ABI handle (see Script) — NodeEditor nodes Get Force Component / Get Force / Set Force (category "Force")
* Testing (InputControls): N/M spawn a team-0/1 emitter ahead of the camera (Shift = focused spear), H = 500-emitter stress burst, F = physics sphere carrying a bubble (knocked back by enemy fields via the force readback), J = territory query grid, B = clear; Force/Debug tweaks draw emitter iso rings + query points

## Profiling
* CPU + GPU scope profiler, part of Core: `Core.Profiler` (`Globals::profiler`), re-exported from `Core.ixx` so plain `import Core;` provides `ProfileScope` everywhere — including inside Core itself. The INTERFACE must not import Core back (cycle): it uses textual std includes + `<cstdint>` types (`uint8_t`...) in its GMF; the implementation unit still imports Core/Core.Windows
* Usage: `ProfileScope scope("Name", EProfileCategory::Physics);` — RAII marker, name MUST be a string literal (stored by pointer). ~15ns hot path: two `__rdtsc`, a thread-local read, one 32-byte store into the calling thread's lock-free single-writer ring (`ProfileTrack`, 32K records/1MiB, overwrite-on-wrap). Thread registration is EXPLICIT-ONLY: every thread that profiles must call `registerThread(name, sortKey)` at thread startup (main does it in `Profiler::initialize`, JobSystem workers in `workerMain` with `SORT_KEY_WORKER + index` — deterministic UI order, no name race with main's `SetThreadDescription`, no registration cost inside a measured scope). There is NO lazy fallback: a `ProfileScope` on an unregistered thread debug-asserts and no-ops in release — a NEW engine thread must register itself at its entry point. All current persistent threads are registered: Main, JobWorkerNN, GPU (named track), TexStream/MeshStream (streamer disk workers), V3 Loader (diffusion model load), JobTimer (`SORT_KEY_BACKGROUND` + offset). Deliberately unregistered: SyntheticMap's transient startup worker pool and the Stress harness's test thread (tracks are permanent — 1 MiB each, never freed — so short-lived helper threads shouldn't have them), and miniaudio's internal audio thread (not ours to hook). Scopes MAY span a JobSystem `wait()`: the open-scope stack (names/categories/segment starts on the `ProfileTrack`) MIGRATES with a parking fiber — `Profiler::suspendScopes` (called at both JobSystem park sites, `fiberWait` + `lockJobMutexSlow`, before the switch-out; closes each open scope's on-thread segment as a record and strips the track back to `Fiber::profileBase`) and `resumeScopes` (called in `runFiber` when resuming a Parked fiber; replays them on the resuming thread's track with fresh segment starts). Timing = sum of on-thread segments, parked time not counted; memory attribution follows the fiber; publication rides the existing `switchDone` protocol. `ProfileScope` therefore caches NO track pointer — ctor and dtor each address the CURRENT thread's track, and the dtor closes the segment started at the last resume (start read from `m_openStarts`, LIFO debug-asserted by name). Scopes nested past `MAX_OPEN_DEPTH` (32) cannot migrate (asserted in suspend). `EProfileCategory` = one entry per library (colors/names via `profileCategoryColor/Name`); records carry depth so the UI needs no hierarchy reconstruction
* Records are pushed at scope END (so each ring is ordered by end time — `snapshotTrack`'s backward scan early-outs on it, and lap-detection discards torn snapshots). `Profiler::endFrame()` (main loop, after present) pushes a frame-boundary mark (512-frame ring) and re-anchors the rdtsc<->QPC calibration (ratio estimated over the whole run; `ticksFromQpc` is how GPU timestamps land on the CPU timeline). `initialize()` runs FIRST in main (registers main thread as "Main", ~0.5ms initial clock calibration). ## Memory
* Allocation tracking + treemap visualization, part of Core: `Core.MemoryTracker` (NOT re-exported from Core.ixx — its only consumer is UI's Memory panel, which imports it explicitly). `Globals::memoryTracker` attributes every engine allocation to the PROFILE-SCOPE PATH open on the allocating thread: Core's allocators + aligned operator new/delete call `g_memoryAllocHook/g_memoryFreeHook` (Core.Allocator, null until installed — one relaxed load overhead; alloc hook fires AFTER allocation, free hook BEFORE release so a recycled address can't race its own entry), the hook reads `ProfileTrack::m_openNames/m_openCategories` (the open-scope stack ProfileScope maintains, owner-thread-only) and walks/builds a `MemScopeNode` tree (4096-node pool, lock-free child scans by name-literal pointer, spinlock creation). * Profiler + MemoryTracker construct at STATIC INIT (`#pragma init_seg`: allocator `.CRT$XCA` → profiler `XCA2` → tracker `XCA3`), so every ordinary global's static-init allocations are already tracked and ProfileScopes in static initializers work. ## Threading
* Fiber-based work-stealing job scheduler (depends only on Core; replaced the old unused coroutine `Core.JobSystem`). Jobs run ON Win32 fibers, so `wait()` inside a job PARKS the fiber and frees the worker to run other jobs; the fiber resumes on whichever worker services the resume queue — possibly a different thread, which is why the root CMakeLists compiles everything `/GT` (fiber-safe TLS): job code must not cache `thread_local` addresses across a wait
* `Globals::jobSystem` (`JobSystem`): `initialize()` MUST run on the main thread (registers it as the helper context: main-thread `wait()` runs jobs instead of blocking; unregistered threads block on the counter atomic). `shutdown()` from main before exit — joins workers while other globals still live. `submit(callable, priority, &counter, name)` / `submitDelayed(delaySec, ...)` (min-heap + dedicated timer thread) / `wait(counter)` / `parallelFor(begin, end, grain, func)` (shared atomic cursor, caller participates, safe to nest inside jobs). Callables store INLINE in the 128-byte `Job` (`Job::StorageSize` = 72; static_asserted — capture a pointer to bigger state). `JobCounter`: add-before-submit is internal to submit; decrement-to-zero resumes parked fibers, notifies blocked threads. Counters/data captured by reference must outlive the wait (fiber stacks make stack-locals safe when the same scope waits)
* Scheduling: per-context Chase-Lev steal deque (`Threading:StealDeque`, fixed capacity, owner LIFO / thieves FIFO) + 3 shared Vyukov MPMC priority rings (`Threading:MPMCQueue`) + resume queue + free-fiber/job-pool rings — everything preallocated in `initialize`, hot paths lock-free, zero runtime allocation. Worker pop order: resumed fibers, own deque, High/Normal/Low rings, steal (random victim). A worker's own continuations always go to its LOCAL deque regardless of priority (fork/join locality); priorities order the shared rings only. Idle workers spin briefly then sleep on an eventcount (`m_wakeEpoch` atomic wait/notify, Dekker-paired with `m_numSleepers`); on exhaustion (pool/queue full) submits execute INLINE with a debug assert — raise the `JobSystemDesc` capacities
* `Threading:JobSync`: `JobMutex` (fiber-parking mutex: contended lock inside a job parks the fiber, main helps, external threads block; barging, standard lifetime contract — use for long exclusive sections like V3 inference so waits hold a fiber, not a worker), `JobEvent` (manual-reset over `JobSystem::signal(counter)`, idempotent signal), `PerWorker<T>` (cacheline-aligned per-context slots via `getWorkerIndex()`/`getNumContexts()`, `.local()`/`.forEach()` — the substrate for per-worker command queues/dirty lists; never cache `.local()` or the index across a `wait()`)
* Job cost heuristic: graph nodes are wall-time EMA'd (`EJobFlag_Timed`, min 1µs so all-cheap graphs rank by chain depth; parked waits count — they occupy critical-path time) and each `run()` recomputes critical-path ranks in one reverse-index walk (edges are forward-only), sorts roots rank-descending and promotes Normal-priority nodes in the top rank quartile to the High ring (`Job::effectivePriority`; user High/Low respected; threshold = previous run's max). `getJobCostUs/getJobRankUs(JobId)` = free per-node profiling. `parallelFor(begin, end, JobCost&, fn)` auto-grains: caller-owned `JobCost` tracker (seed = expected ns/item) targets `JobSystemDesc::parallelForTargetChunkNs` (25µs) chunks, runner timings feed back per call. Ad-hoc submits are deliberately untimed (two clock reads on ~100ns jobs); `Job::StorageSize` is now 64 bytes
* `JobGraph` + `JobResource` (`Threading:JobGraph`): declared-access DAG. `graph.addJob(name, fn).reads(resA).writes(resB).after(id).priority(p)` derives hazard edges render-graph-style in declaration order (reader <- last writer; writer <- readers since last write); same-resource reads run in parallel, and the schedule itself is the synchronization — no locks anywhere. Edges always point earlier->later declared, so cycles are impossible by construction. `compile()` once (dedupe + CSR successor arrays + initial dependency counts + roots), then `run()`/`wait()`/`runAndWait()` per frame: run only resets the per-job atomics and pushes roots — zero allocation, re-runnable. `JobResource` is a process-unique id created next to the data it names (non-copyable, like Tweak registration)
* Stress harness (`Globals::jobSystemStress`, Threading/Stress tweaks, `update()` from the main loop): benchmark modes (empty-job throughput, parallelFor, a 128-job/16-resource hazard-CHECKED random graph, fiber park/resume) publishing ms + jobs/ms, "Run self test" one-shot correctness pass (sums, coverage, hazard ordering, fiber waits, delayed jobs) into the log, scheduler rates under Threading/Stats
* Invariants (each guards a race that was actually hit; torture-tested via a temp console target, the way to re-verify changes here): a waiter may FREE the counter the instant it observes completion, so `isDone` is "the FULL value is zero", fiber-wait registrations ride the count atomic's high 8 bits (`JobCounter::WaiterInc`) keeping the value nonzero until their owner removes them, the zero transition claims the wait list with ONE `exchange` of a taken-sentinel (late registrants see the sentinel - strictly after that exchange - and back their own bit out), and the only post-zero touch is an address-only `notify_all`. A parked fiber's wait node lives on its stack (signaler reads `next` before resuming, spins on `switchDone` until the fiber fully switched out); `runFiber` reads the fiber state BEFORE publishing `switchDone` (the fiber may finish elsewhere and be reused); recycling freelists are LIFO tagged-index stacks, NOT rings (a preempted ring pop makes pushes see phantom "full"/"empty" - this exhausted the job pool in practice); inline helping in `wait()` is depth-capped (a helped job that waits helps again - unbounded recursion). `Job` is 128 bytes / two cache lines (static_asserted). Don't hold a fiber wait across `shutdown()` (asserted)

## Procedural
* The procedural world layer: diffusion-model terrain, FFT ocean, object scattering, terrain physics, and the camera-centered world-data bakes they share. Sits above the renderer (links RendererVK + File + Spatial + Physics; onnxruntime is PRIVATE and never leaks, like box3d in Physics). Not entity-based and no `Globals` here: main.cpp owns `TerrainStreamer terrain` / `TerrainCollider terrainCollider` / `OceanGenerator ocean` / `ScatterSystem scatter` and updates them per frame in that order (after entity updates, before `present`), wiring `ocean.swellTravelAngle()` -> `terrain.setFlowWindAngle` before `terrain.update`, then `terrainCollider.update(camera.position, terrain.activeClimateMaps())`, `ocean.update(renderer, camera, terrain.activeTerrainData(), terrain.seaLevel())` and `scatter.update(..., terrain.activeClimateMaps())`
* `ITerrainSampler` (`:TerrainSampler`): THE terrain field interface everything consumes — pure virtual, pure functions of world (x, z), seeded/thread-safe/world-continuous, held as `shared_ptr<const>` (workers finish against old maps across config rebuilds). `samplePoint`/`sampleGrid` fill a `TerrainPoint` (height, water level, altitude, temperature + SEA-LEVEL baseline, humidity, fog, flow angle) in ONE evaluation — wide-area consumers must use `sampleGrid` (hoists per-point overhead; for V3 one lock per tile instead of per texel); single-field samplers exist for point consumers. `ESampleDetail::Coarse` lets km-scale bakes read a cheap level. One `lapseRatePerMetre()` for the whole world (temperature = baseline + lapse x height; per-texel rates measured redundant)
* `TerrainGenV3` (`:GeneratorV3`, implementation under `Private/Diffusion/`): the terrain generator — an ONNX diffusion pipeline port (ONNX Runtime + DirectML, 2.28 GB of models downloaded/loaded once per process, then RESEEDED never reloaded, so sampler rebuilds are cheap). Generates 256x256 TILES (7.68 km at the native 30 m/px; `metersPerPixel` is a UNIFORM world scale) behind the sampler interface: a point read is a bilinear tile fetch, a cold tile takes ~1.5 s with inference serialized by a fiber-parking `JobMutex` (tile store is not thread-safe; all procedural jobs call in — their waits park fibers, not workers), and concurrent requesters of the same tile park on a per-tile `JobEvent` (one generation serves all). Sub-30 m relief is slope-masked procedural noise on top (`:Noise` `NoiseField`, fbmEroded). `isReady()` gates everything until models are loaded (else a flat world bakes into caches). Diffusion .cpp TUs compile `/fp:precise` + `/wd5050` — load-bearing; the why and the .ixx-declarations-only rule it forces are documented in Code/Procedural/CMakeLists.txt
* `TerrainStreamer` (Tweaks "Terrain*"): render-only chunk streaming — a bounded LOD ring of chunks around the camera, generated on up to "Gen jobs" self-continuing Low-priority pump jobs (default 2; `kickPump(n)` CAS-claims slots + exit-recheck protocol; nearest-first pick at dequeue kept; warm-tile mesh builds overlap cold V3 waits since those park fibers; `createMeshScene` runs IN the pump — audited pure — so main only does ObjectContainer::initialize; ring enqueue scan gated on ring/pending change; splat bake = one Low job wrapping a parallelFor). ScatterSystem uses the same multi-pump protocol ("Scatter/Gen jobs") (`generateChunk` from `:TerrainGenerator`: world-space sampling so chunk/LOD boundaries agree, skirts, seabed included) and bridged to ObjectContainer/RenderNode + SpatialEntry on the main thread; chunks leaving the ring free all GPU residency (`~ObjectContainer`). Owns THE world datum + rules other systems must agree with, handed out not duplicated: `seaLevel()`, `activeWaterReach()`, `activeFlowField()`, `activeClimateMaps()`. Also bakes the shared TERRAIN-DATA MAP (2 cascades near/far, RGBA32F: height, water level, bit-packed fog|flow|temp|humidity, macro altitude -> `Renderer::setFogTerrainHeightMap`; consumed by volumetric fog terrain-follow, the ocean's water depth/level (GPU via terrain_height.inc.glsl + a CPU copy via `activeTerrainData()` for buoyancy/wind steering), terrain coloring) and the terrain splat textures (BC-baked to Assets/Local/TerrainTex on a background thread at startup, climate-box picked)
* `HeightMapBaker` + `applyWaterReach` + `applyFlowField` (`:HeightMapBaker`): the async snapshot bake driver both maps use — one Low-priority job in flight (JobCounter-polled, params boxed past the 64-byte job capture), re-bakes on camera drift > range/4 or when sampler identity/ranges/rules change (configs carry `operator==` so the tweaks stay live), center snapped to the coarsest texel lattice. `WaterReach`: chamfer distance-to-ocean sinks the baked water level under ground the ocean cannot reach (V3 reports sea level planet-wide; this is what keeps swash/beaches off inland hollows). `FlowField`: 8-bit per-texel flow direction (0 = none, 1..255 = angle/2pi) — toward nearest land through the surf zone (dead-reckoning feature transform + easing back to the swell heading offshore + mask-weighted vector-sum box blur so beach downhill never cancels it), downhill everywhere else; baked into BOTH maps' flow bits
* `OceanGenerator` (Tweaks "Ocean*"): CPU side of the FFT/Tessendorf ocean — a camera-following geometry clipmap (fixed cell size per ring so mips don't morph with camera motion, CDLOD edge morph; a "Horizon band" quad ring extends the outermost ring's morphed lattice to the camera far plane so the sea always meets the horizon — drawn FLAT (no wave displacement, "Horizon level offset" shifts it) and exempt from the land culls) over `RendererVKLayout::EPipelineIndex::Ocean`, split into SECTORS terrain-chunk style (ring 0 whole, 8 rectangular blocks per outer ring, 4 horizon-band sides — each an ObjectContainer/RenderNode + SpatialEntry on `SpatialLayer_Terrain`, all sharing one snapped transform, borders duplicating identical vertices so no seams): the Spatial Main-pass gate skips off-screen sectors on the CPU (ocean is PASS_MAIN only, so a culled sector pushes nothing), a "Dry sector cull" skips sectors whose whole footprint is buried per a conservative per-block max-depth grid over the baked terrain data AND sits entirely inside the streamed-mesh radius (deep inland the ocean costs nothing; past the mesh the sea always fills the horizon, matching the VS cull's own fence). The horizon band is exempt from BOTH under-terrain culls (its vertices carry a NEGATED cell size as the flag): its triangles span ring-edge-to-far-plane, so they break the vertex cull's ±3-cell footprint assumption and one buried vertex would tear a huge slice out of the horizon, and the GPU per-instance frustum cull refines the rest; the simulation (spectrum -> IFFT -> displacement/gradient maps, re-evaluated every frame so every param is live) is `OceanSimulationPipeline` in RendererVK. Bakes NOTHING itself: shoaling, surf, swash and the VS land cull all read the streamer's shared terrain-data map (GPU: terrain_height.inc.glsl cascades; CPU: the `activeTerrainData()` snapshot adopted each update). `sampleWaterHeight` = CPU buoyancy field from the GPU displacement readback (App wires it into `PhysicsWorld::setWaterSurface`); its `sampleDisplacement` is a full CPU MIRROR of `oceanSampleDisplacement` (ocean_wave.inc.glsl) — shoal fades, swash run-up/backflow/drawdown, waterline floor, and the `swashReach` estimate Renderer.cpp packs into the UBO. "Ocean/RT" tweaks budget the per-pixel scene rays (refraction range = underwater visibility, reflection range + roughness cutoff, and a camera-distance ray cutoff that falls back to the analytic bottom/sky). The shader is what you see and the mirror is what floats on it, so a change to either without the other is a silent bug (bodies sinking through drawn waves / floating on dry sand); returns -FLT_MAX only past the run-up band, and inside it the drawdown floor sinks the surface under the sand, which is what beaches bodies. WIND CONVENTION: the spectrum's dominant term travels AGAINST `windDirection` — the swell heading is `swellTravelAngle()` = wind angle + pi; `steeredWindAngle` turns the SIM wind toward the baked shore flow around the camera (rate-limited slew, votes from the CPU shore copy) so waves roll inland — per-pixel domain rotation is disabled in ocean_wave.inc.glsl (creases; see the comment there before reviving it)
* `TerrainCollider` (Tweaks "Terrain/Collision"): terrain physics — a camera-centered ring of small static triangle-mesh collider tiles (default 32 m tiles within 96 m, 1 m sample spacing = the render LOD0 lattice, generateChunk's triangulation, so bodies rest exactly on the drawn surface). Never touches the render chunks (LOD0 is ~500k tris; colliders only need the ground near dynamic bodies): each tile is sampleGrid'd + BVH-built (`createCollisionMesh` is standalone/thread-safe) on ONE in-flight Low-priority job (JobCounter-polled), nearest-first; the main thread only creates/destroys the static bodies (layer "Terrain"). Tiles clear on sampler identity change / disable, evict with half-a-tile hysteresis. Verify with Physics/Debug/Draw colliders
* `ScatterSystem` (Tweaks "Scatter"): trees/rocks/grass over the terrain — config is two tables in Scattering.cpp (`SCATTER_ASSETS`: .oc-referenced models with footprint/scale/slope settings; `SCATTER_RULES`: climate ATTRACTORS in real units (C, mm/yr) with Gaussian density falloff — no biome enum). Cell placements computed deterministically on a Low-priority pump job (same claim protocol as TerrainStreamer) from the SAME sampler the terrain renders (footprint dart-throw, cluster noise, slope/altitude bands), bridged to RenderNodes; per-rule `viewDistance` spawns/despawns instance groups without regenerating cells; everything regenerates when the sampler identity changes

## Network
* Winsock UDP/TCP + a reliable-UDP game protocol (depends only on Core; Ws2_32 + Bcrypt linked PRIVATE). Module partitions `:Address`, `:Serialization`, `:Socket`, `:Crypto` (internal, nothing exported), `:Reliable`, re-exported from `Public/Network.ixx`. IPv4 only, wire format is raw little-endian bytes â€” no versioning/compat, both ends must match (`protocolId`). Consumed by Entity's `NetworkManager` (see the Entity section's MULTIPLAYER bullet); `NetHost` is strictly single-threaded â€” every call from the main thread
* `:Serialization`: `NetWriter`/`NetReader` over a caller-provided byte span â€” trivially-copyable `write<T>`/`read<T>`, varint (LEB128 + zigzag), strings, unorm/snorm/`writeQuantized<UInt>(v, min, max)` float quantization; overflow-safe (check `overflowed()`), reads are zero-copy views
* `:Socket`: non-blocking RAII wrappers â€” `UdpSocket` (big SO_RCVBUF, SIO_UDP_CONNRESET disabled, optional broadcast), `TcpSocket`/`TcpListener` (TCP_NODELAY, `poll()` resolves connects), `TcpMessageStream` (uint32-length-framed messages with partial send/recv buffering), `netResolveHost` (blocking DNS). Winsock initialized lazily on first open
* `:Reliable`: `NetHost` â€” symmetric client/server/p2p over one `UdpSocket` (two hosts `connect()`ing to each other resolve the simultaneous handshake, tie-broken on connect salts). Poll model like the rest of the engine: queue with `send(peer, bytes, ENetDelivery, channel)`, per-frame `update(dt)` pumps/retransmits/flushes (messages batched into â‰¤`maxPacketSize` packets), drain `takeEvents()` (Connected/Disconnected/Message). Deliveries: Unreliable, UnreliableSequenced (stale-dropped), Reliable (ordered + guaranteed, acked via packet seq + 32-bit ack bitfield piggybacked on every packet, RTT-based retransmit, fragments transparently up to `maxMessageSize`) â€” on up to 8 independent channels (index rides in the message kind byte, zero wire cost) so bulk transfers don't head-of-line-block other reliable streams. 4-way anti-spoof challenge handshake (responder is stateless until the challenge round-trips: `serverSalt = HMAC(hostSecret, addr|salt|flags)`); `NetHostConfig::encrypt` adds ephemeral ECDH P-256 key agreement in the handshake + AES-128-GCM per payload packet (+16B tag, nonce = sender role + implicit 64-bit packet counter; Windows CNG, hardware AES) â€” secure against spoofing/eavesdropping/tampering, not an active MITM (unauthenticated keys). Keepalives/timeouts, per-peer RTT/loss stats, and live-editable link simulation (`simPacketLoss`/`simLatencyMs`/`simJitterMs`) in `NetHostConfig`. ABUSE LIMITS (`NetHostConfig`, all enforced before any parsing/allocation): a per-SOURCE-ADDRESS packet token bucket (`maxPacketsPerSecPerAddress`/`packetBurstPerAddress`) in a FIXED 512-entry table — a per-address map would itself be the memory attack, so slots are hash-indexed (splitmix finalizer: raw address bits cluster by subnet/port) and a foreign slot is only stolen once its owner has gone quiet enough to have refilled, or a flooder could evict an active peer and reset its own budget; `maxPacketsPerUpdate` bounds one update()'s work globally (the socket keeps yielding under a flood, so per-address limits alone still let one frame run unbounded); `maxPeersPerIp` stops one machine completing handshakes on many ports to eat every slot (the challenge proves reachability, not scarcity); `maxQueuedReliablePerChannel` disconnects (`ENetDisconnectReason::Overflow`, latched in `sendWindowOverflow` and acted on in update() — freeing a peer inside send() would break sendToAll's loop) a peer that keeps its connection alive while never ACKING, which otherwise grows the reliable send deque without bound. `NetHostStats::packetsDroppedPerSec` surfaces rate-limited traffic (shown in the server title bar). An UNUSED rate bucket must be claimable on the first packet (testing an empty bucket's refill rejects every new address)

Skinned/animated scenes always bypass the cache (skeleton/clips are not serialized). Delete `Assets/Local/Cooked/` to force a full recook
* `AssetParser` (`File:AssetParser`): the text format behind all engine text assets (.pre/.oc/.anm/.apl). Indentation-defined hierarchy of `AssetNode` (key + values + children), `#`/`//` comments, quoted strings, comma-separated vectors; `loadAssetFile`/`parseAssetText`/`writeAssetText`, case-insensitive `find`, typed accessors with fallbacks. `File:ObjectDescription` parses .oc declarations into `ObjectContainerDesc` (`loadObjectContainerDesc`) — lives here (not Entity) so Procedural's scatter assets import through .oc files too
* `FileSystem` sets the working directory to `Assets/` at startup

## Input
* SDL3 event pump; listener objects (`addKeyboardListener()`, `addMouseListener()`, `addSystemEventListener()`) with std::function callbacks
* `GizmoController` (in Input, OWNED BY THE UI): spawns `Entities/Gizmo.pre` and drives it â€” follows the Scene panel selection, constant apparent screen size, handle set switches with `EGizmoMode` Translate/Rotate/Scale (T/R/G), mouse-drag manipulation writes back to the entity (a kinematic/static physics body does NOT follow — see PhysicsComponent). # Asset files (all text formats parsed via `AssetParser`, registered by `AssetRegistry`)
* `.oc` (ObjectContainer): a model source + import options (`Path`, `MergeNodes`, `PreTransformVertices`, `DecimationFactor` (< 1 meshopt-simplifies base geometry at cook time; cache-only, so skinned/procedural containers never decimate), `MaterialOverrides` with `PipelineIdx`/`ExcludeFromRayTracing`/texture overrides) plus named `StaticMesh`/`SkinnedMesh` spawnable entries (`Node` path within the model; SkinnedMesh adds `Type Humanoid/Generic` + optional bone mapping). Skinned containers MUST keep `PreTransformVertices false`
* `.pre` (Prefab): a named entity (hierarchy) â€” `Prefab <name>` root with `Component Render/Animator/Script/Physics/Audio/Particle/Force/Light/Scene` children; `Component Scene` nests child `Prefab` references. `Component Audio` nests `Sound <alias>` entries, each with an optional `Select` and one or more `Path <file>` clips whose own child lines are that clip's playback settings. Render references a spawnable (`StaticMesh <name>`) or `ObjectContainer <name>` + `Node`, plus `Position/Rotation/Scale`. Spawn by prefab name (`world.spawn("physicsCube", ...)`) or file path (`world.spawnAssetFile`)
* `.anm`: `Animation <name>` clip entries â€” source `ObjectContainer` (fbx), `Loop`, `Skip` (channels), `Event <name> <normalizedTime>` notifies (fired into the entity's script/animator `onEvent`)
* `.apl`: `Animator <name>` graph â€” `Parameter`s (Float/Bool/Trigger), `Clip` bindings, `BlendSpace1D` with `Sample`s, `StateMachine` (states with `Play`/`SpeedParam`/`SpeedScale`, `Transition`/`AnyTransition` with `Condition`/`ExitTime`/`Fade`)
* `.scr`: visual script = generated C++ + `//@graph` node metadata (see Script)
* `Assets/Local/` is generated output (compiled SPIR-V + shader source dumps for Aftermath, compiled script DLLs/PDBs, cooked scene caches `Cooked/*.vsc` + converted `.dds`) â€” never hand-edit
